# Паспорт: проект, справочник в браузере и хранение

**Что это.** Запись проекта (участок, документы, история, метки происхождения), файлы проекта и справочника, версии справочника у проекта. Базы данных нет (решение пользователя 29.09.2026): всё в браузере и в файлах. Целевая схема с сервером — `docs/01_architecture.md`.

## Хранение сейчас

- **Файл проекта** (формат `finmodel-project`, версия 1) — один JSON: `project` (запись проекта как есть: участок, метки происхождения, документы, история), `reference` (полная версия справочника, на которой посчитан проект), `files` (документы по id: имя, тип, размер, sha256, байты в base64). На сервере `project` ложится в таблицу проектов, `files[].data` заменяется ссылкой на хранилище файлов, остальное без изменений.
- **Все проекты одним файлом** (формат `finmodel-projects`, версия 1): `projects` — файлы проектов как выше, `reference` — все версии справочника браузера. Нужен для переноса на другой компьютер или новый адрес сайта (хранилище браузера привязано к адресу). Открывается той же кнопкой «Открыть из файла»; справочник из файла добавляется, только если продолжает справочник браузера, иначе проекты сохраняют свою версию; совпавшие по названию проекты — «Заменить», «Создать копии» или «Не открывать их» одним выбором (`bundlePlan`).
- **Открытие проекта из файла**: документы получают новые id; если проект с таким названием уже есть — вопрос «Заменить» или «Создать копию». Если версии справочника из файла нет в браузере или она другая, проект хранит её у себя (`assumptionsSnapshot`) и считается на ней до кнопки «Обновить».
- **Файл справочника** (формат `finmodel-reference`) — все версии по порядку. Загрузка добавляет новые версии; если истории разошлись, версии браузера с точки расхождения заменяются версиями из файла, а проекты на заменённых версиях сохраняют свою версию.
- **Правка справочника**: в интерфейсе правятся стандартные значения компании: значение, статус, «Откуда», пояснение. Сохранение создаёт новую версию с автором и описанием; проекты переходят на неё кнопкой «Обновить», переход пишется в историю проекта. Налоги, ставки по закону и нормативы регионов в интерфейсе не правятся: они привязаны к документам и меняются через `data/*.yaml`.
- **«Нужно значение» в справочнике** — только для пустого значения, без которого расчёт не идёт. Пустые необязательные значения (пороги отбора вариантов, надбавки по стадиям, комиссии банка, скидка к ставке, коэффициент апартаментов) — «не обязательно» с пояснением, что происходит без них; безрисковая ставка — «заполняется сам» (кривая ОФЗ в проекте); незаполненный норматив региона — «вводится в проекте» (`OPTIONAL_IF_EMPTY`, `AUTO_FILLED` в `reference.ts`). Решение пользователя 13.11.2026: ручного ввода — минимум.

## Поиск по адресу

- Первый поиск — сам, когда проект с адресом открыт впервые; повтор — кнопка «Найти данные по адресу» на шаге «1 Участок». Найденное хранится в `project.geo` (адрес запроса, адрес геокодера, точка, регион, округ и район, дата).
- Москва: после поиска по адресу сервис смотрит портал открытых данных Москвы по точке, результат — `project.mos` (городские участки в точке, зоны охраны и территории памятников, дата). Один городской участок — его номер, квартал и ВРИ сразу «из источника», форма права для земли города — оценка «аренда» (ст. 39.6 ЗК РФ: под строительство — аренда на торгах); несколько — финансист выбирает. Кадастровая стоимость — оценка `cadastralValueEstimate` (площадь × средний УПКС квартала по группе ВРИ, распоряжение ДГИ № 214856), если она пуста или была оценкой. Городского участка в точке нет — форма права «собственность» (оценка). Площадь проекта не меняется: если в реестре другая — сообщение. Значения из документа проекта не заменяются. Зоны и территории памятников — строки зон с особыми условиями с id `mos-…` (площадь на участке не известна); при повторном поиске заменяются только они.
- Здания под снос (Москва): `project.mos.buildings` — здания адресного реестра (набор 60562) у участка: на участках проекта или городских участках в точке (`KAD_ZU`), в том же доме, что адрес геокодера (все строения), или здание, в котором точка (`projectBuildings`). Площадь контура — по границе здания (`footprintArea`), этажность — OpenStreetMap `building:levels`, если центр здания OSM внутри контура. Финансист отмечает здания и вводит недостающую этажность; `applyDemolitionPick` пишет в `demolitionGfa` оценку «контур × этажность, сумма» с основанием и запоминает отметки в `site.demolitionPick`. Площади и этажности в реестре нет (проверено 18.11.2026); НСПД не используется.
- Регион: пустой — заполняется «из источника»; совпал с введённым — получает метку «из источника»; из документа — не меняется; другой — не меняется, выводится сообщение.
- Точка: ставится, если её не было или она стояла по прошлому поиску; поставленная вручную не меняется.
- Несколько разных домов — финансист выбирает; нашлась только улица — предупреждение.

## Ловушки

- Пустое значение не равно нулю: показатель «не учтено» (`docs/00` §5).
- Метки происхождения — только четыре из `docs/00` §5; тексты меток — `ORIGIN_LABEL`.
