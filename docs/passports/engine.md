# Паспорт: расчётное ядро (packages/engine)

**Что это.** Чистый TypeScript без интерфейса и базы: вводные проекта → значения всех формул и след для паспорта показателя. Экраны только вызывают ядро.

## Как устроено

- **Вход** — `ProjectInput` (`src/types.ts`): `values` (значения проекта по ID параметра), `standard` (стандартные значения компании той версии справочника, на которой создан проект), `mode`. Порядок подстановки: своё значение проекта → стандарт компании → регион → значение по умолчанию из `parameters.yaml` (`ValueOrigin`).
- **Формулы** — `src/modules/<модуль>.ts`: одна формула из `formulas.yaml` = одна функция `F_<МОДУЛЬ>_<ИМЯ>` с тем же ID. Реестр — `src/registry.ts` (`FORMULAS`; формулы анализа участка — отдельно, `ANALYSIS_FORMULAS`).
- **Порядок** — топологическая сортировка по `depends_on` (`src/context.ts`, класс `Engine`). Циклы запрещены. Связи через прошлый месяц (`lag_depends_on`: ставка ← покрытие за t−1 ← долг ← проценты) считаются помесячно группой (`stepwise`: эскроу, FIN, TAX).
- **Выход** — `ResultSet`: значения формул с входами (`trace`), значения параметров с происхождением, сообщения (`error` блокирует отчёт, `warning`, `info`; у повторяемых — постоянный `key`).
- **Модули по порядку** (`ENGINE_MODULES` в `src/index.ts`): TIME → TEP → LAND → CAPEX → SALES → ESC → FIN → TAX → CF → KPI → CHECK. Плюс SITE, MARKET, VAR — анализ участка ([site-analysis](site-analysis.md)).
- **Проект целиком** — `src/project.ts`: `projectInput` (вводные из проекта и справочника), `projectHorizon` (горизонт до последней вехи + раскрытие эскроу), `computeProject`, пара режимов `modePair`.
- **Режимы**: `normal` — расчёт сервиса; `legacy` — «как в исходном Excel», воспроизводит исходник один в один ([legacy](legacy.md)).
- **Пояснения** — `src/explain/`: `how.ts` («Как посчитано» на числах проекта), `sales-summary.ts` (продажи по продуктам), `periods.ts` (месяц → квартал, год), `site-view.ts` (строки экранов анализа).
- **Вспомогательное** — `src/lib/`: даты ISO в UTC, IRR/XIRR, S-кривая, кварталы исходного Excel, форматирование чисел по-русски.

## Правила кода

- В `src/modules/**` нет числовых литералов, кроме `0`, `1`, `12`, `365` и индексов (правило ESLint и `test/no-magic-numbers.test.ts`).
- Каждая формула модулей из `IMPLEMENTED_MODULES` реализована, и наоборот (`test/coverage.test.ts`).
- Деньги — `decimal.js`, даты — строки `ГГГГ-ММ-ДД`.
- Правило, которого нет в спецификации, не додумывается: формула выдаёт понятную ошибку о недостающем вводе.
