# Паспорт: сборщик данных

**Что делает.** Принимает запрос от сервиса, сам обращается к источнику с сервера в России и возвращает ответ как есть, с названием источника, адресом запроса и временем (`fetched_at`). Ничего не рассчитывает: расчёт — в `packages/engine`.

**Зачем.** НСПД, Росреестр, открытые данные Москвы и реестр ОКН не отвечают зарубежным серверам (Vercel, GitHub) — проверено `scripts/probe_sources.py`, PR #18.

**Где работает.** VPS в Хостленде, пользователь `finmodel` без root, папка `~/collector`, служба `systemd --user` `finmodel-collector`, порт `127.0.0.1:3300`. Пределы: память 300 МБ, процессор 25% ядра (`deploy/finmodel-collector.service`). Снаружи — через nginx, поддомен `finmodel.orientirgpz.com` (`deploy/nginx-finmodel.conf`; ставит владелец сервера от root).

**Запросы** (`collector.py`):
| Путь | Источник | Токен |
|---|---|---|
| `/health` | — | нет |
| `/v1/geocode?address=` | OSM Nominatim, не чаще 1 раза в секунду | да |

Токен — заголовок `X-Collector-Token`, создаётся при первой установке в `~/collector/.env` и в журналы не выводится. Ответы кэшируются на сутки в памяти. В журнал пишется только путь запроса, без адреса.

**НСПД.** Отвечает программам 403 (проверено 13.11.2026). Кадастровые данные (ВРИ, кадастровая стоимость, права, площадь) вносятся вручную или из выписки ЕГРН, решение пользователя 13.11.2026. Защиту не обходим.

**Российский сертификат.** Российский корневой сертификат Минцифры скачивается с gu-st.ru в `~/collector/certs/` и используется только сборщиком; в систему не ставится.

**Установка.** Workflow «Сборщик данных» (`collector-deploy.yml`) при изменении `services/collector/**`: проверки без сети, затем установка по SSH (`deploy/install.sh`) и проверочные запросы.

**Проверки.** `python3 -m unittest services/collector/test_collector.py`.

**Не входит.** Разбор ответов в поля участка, ПЗЗ, зоны ОКН (isogd.mos.ru не отвечает), apidata.mos.ru (нужен ключ).
